# Validation

`npm test` runs API integration tests against disposable schemas in Neon PostgreSQL. `tests/helpers.mjs` explicitly injects bounded identity and private-object-storage fixtures for regression tests; application metadata uses the real PostgreSQL connection. Tests cover permissions, sessions, uploads, compensation, deep links, notifications, cross-faculty isolation and persistence. Each generated `campuslink_test_*` schema is dropped afterward. `CAMPUS_TEST_DATABASE_URL` may select a dedicated database; otherwise the server-side `DATABASE_URL` is used without printing it.

Historical regression fixtures use `createTestEnvironment({legacyCommunity:true})` by default to keep their FLAA administrator publication and faculty-admin permission checks. This test-only option restores the administrator’s FLAA/French studies selection and enables the retired profile for authorization checks; production seeding still creates Issmail in FSA/Sciences de Données and keeps the professor retired. New student-community tests use `legacyCommunity:false` or invoke the production seed directly. `community-profiles.test.js` verifies the new seed and scoped upgrade preserve authentication, student conversations and academic files while retiring professor conversations; import tests also verify cleanup and read-only local backups.

`npm run test:browser` builds and tests the production bundle with Playwright at port 5174 using the same asynchronous PostgreSQL fixture. It runs filière, community, study, administration, appearance, responsive, optimistic-action, registration and administrative-alert suites sequentially. Cleanup closes event streams, HTTP connections and database pools before dropping the disposable schema. The application schema and real provider accounts/bucket objects are left unchanged. `CAMPUS_CHROMIUM` can point to an existing Chromium executable. Use `CAMPUS_BROWSER_SUITES=filiere` to run the account and private chat flow on its own. These regression suites do not substitute for the separate real Neon Auth/R2 integration checks.

The filière suite provisions accounts through the injected identity-provider fixture with e-mail and an already selected faculty, checks the exact four supplied major catalogs, and verifies setup never asks for the faculty again. General chat remains faculty-wide with no semester selector. The separate private Filière channel groups semester chats into S1/S2, S3/S4 and S5/S6. Tests verify grouped URLs/defaults, persistence after reload, conversations when students visit another group in their own Filière, foreign-Filière privacy, keyboard controls and correct announcement/resource source links. Uploads persist module identifiers and metadata, and protected retrieval rejects anonymous and foreign-faculty users. The academic resource semester remains independent of its private source chat; general uploads require no chat semester. Phone selectors stay inside the header, and tablet/desktop tabs and Arabic RTL remain covered.

`npm run test:chat` runs the student-community browser checks with the current production profile defaults: Issmail in Sciences de Données, public student identities, author-only message deletion, retained library resources, live chat blocking and restoration, one open message menu, keyboard dismissal, and menu bounds on phones, tablets and desktops in both themes and Arabic RTL. It uses its own disposable schema and HTTP port.

Administration checks also verify that correcting a general document title preserves its semester and module, while explicit semester/module edits persist in PostgreSQL and the module catalog. Appearance tests inject bounded authentication and storage error responses to check French, English and Arabic error rendering without creating real provider accounts or bucket objects.

The responsive suite checks phone, tablet and desktop headers at 390, 768, 1024, 1280 and 1440 pixels; navigation collapse increases the chat area, keyboard drawers trap focus and restore it on Escape, and phone Settings exposes language and appearance controls. It measures actual text contrast and size in both themes and verifies persistent preferences and Arabic RTL.

`CAMPUS_BROWSER_SUITES=optimistic node tests/run-browser.mjs` holds and fails real browser requests to verify immediate sends, deletes, pins, reactions and bookmarks before the server responds. It covers concurrent pending sends, stale bootstrap snapshots, SSE reconciliation before acknowledgement, retry with the same client UUID, failed-send discard, canonical announcement IDs and isolated rollback. `optimistic.test.js` additionally checks account/ban boundaries, author-scoped UUID matching and late responses after target deletion. `message-idempotency.test.js` verifies real PostgreSQL uniqueness, concurrent retry and transactional notification scope.

Screenshots in `../screenshots/` record desktop, mobile and Arabic RTL inspection. They use illustrative local accounts and never publish externally.

`CAMPUS_BROWSER_SUITES=registration node tests/run-browser.mjs` exercises signup, waiting status, exact faculty-major catalogs, administrator approval/refusal, confirmed student deletion, old-session revocation and anonymous retention of shared academic files. It requires the runner’s disposable-fixture flag before creating or deleting test accounts. `registration.test.js` separately verifies the protected API gate, role/status injection resistance, provider compensation, cross-faculty admin notices, admission idempotency and live updates when notifications are muted.

`CAMPUS_BROWSER_SUITES=admin-alerts node tests/run-browser.mjs` verifies that only new administrative requests create popups: reports, authenticated/anonymous contacts and registration requests. It checks global and faculty permissions, quiet ordinary chats, muted live queues, read/dismiss behavior, duplicate refreshes, reload baselines and French/Arabic phone layouts. `admin-notifications.test.js` covers account changes and incoming-notice deduplication without a database.

`node --test tests/pwa.test.js` checks the manifest, real icon dimensions, installation gestures, secure-context registration and the public-only service-worker cache. `node tests/pwa.browser.mjs` uses mocked application APIs with the local frontend, exercises the actual worker and offline page, and verifies that private API/document/avatar responses never enter Cache Storage. PWA/browser checks do not create production accounts or documents.

With the frontend running, `CAMPUS_PHONE_ORIGIN=http://192.168.1.102:5173 node tests/phone-send.browser.mjs` tests sending on the actual HTTP LAN origin, where the browser lacks native `crypto.randomUUID`. Substitute the current local-network address. Every API response is mocked, including message POSTs and event streams; no application accounts or documents are modified. It holds acknowledgements to verify immediate messages, an empty and usable composer, concurrent sends, stale refreshes, SSE reconciliation, failure feedback and retries with the same UUID. It also checks replies, paired major groups, read-only channels and touch targets on small phone/tablet viewports in both themes and French/Arabic. `client-id.test.js` validates native UUID selection and cryptographic fallback UUIDs against the message contract.

`node tests/live-chat.browser.mjs` checks incoming messages in the currently open chat with fully mocked APIs and streams. It covers reconnects, foreground/network recovery, missed events, sustained bursts, serial slow snapshots, request deadlines, hidden/offline polling suspension, paired-major scope, pending/failed drafts and session/block gates. Browser timers are installed before application startup so the ten-second reconciliation interval and twenty-second deadline are exercised. `live-updates.test.js` checks coalescing and account cleanup; `database-connection.test.js` injects a pool error to verify the API cannot crash or log connection details from a failed idle client. These checks do not create or change real profiles or messages.
