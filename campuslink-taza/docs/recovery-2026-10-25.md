## Correction terminée

Google désactivé et migration `036_google_oauth_sessions.sql` entièrement absente : le serveur et sa sonde de santé acceptent le schéma précédent. Les connexions classiques utilisent alors leur comportement antérieur, sans accès aux cinq tables OAuth absentes. Cette compatibilité ne fournit pas les nouvelles garanties d’admission durable avant migration.

Google demandé, même avec une configuration de domaine invalide : la migration complète reste obligatoire. Une application partielle, des checksums modifiés, une autre migration en attente ou des objets applicatifs manquants restent bloquants. Une base déjà migrée conserve les admissions durables même si Google est désactivé. Après application de `036`, redémarrer les processus API pour activer cette politique ; elle ne bascule pas à chaud.

Le démarrage ne lance aucune migration. Les tests utilisent PostgreSQL local jetable et des fournisseurs simulés, sans connexion Google réelle, envoi d’email ou modification de la base de production.
